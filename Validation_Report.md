# Отчёт проверки FunCombat

Источник: `FunCombat_Renamed2.rbxl`, SHA-256 `a14ab714b5b3233a8e05fc5567ce1b9a7dc700ced2ccb2e13771c025f64142b0`. Исходник не изменён; точная копия включена в полный архив. Геометрия и визуальное сходство не проверялись по просьбе владельца.

## Проверки, выполненные вне Roblox

- Исходный бинарный DOM прочитан через rbxmk 0.9.1 и дополнительное восстановление бинарных строк. Сохранены обе исходные карты, Terrain, окружение, спавны и авторитетные R6 тела.
- Экспортированы 129 презентационных пакетов, 829 Instances, все 47 KeyframeSequence: 4 581 Keyframe и 33 108 Pose. Шесть оружий, оба исходных костюма и их три embedded UnionOperation включены. Внутренние parents, references и companion model membership согласованы.
- Сохранены 396 ProximityPrompt в активной карте/двух шаблонах/шести шаблонах персонажа. Скопированы исходные параметры клавиш, удержания, дистанции, line of sight и UI offset. Имена/подписи кодируются; mapping находится в config/identifiers.json. Актуальная доступность определяется серверным состоянием и владением.
- Protocol 4, две RemoteEvent, одна RemoteFunction, Version/BuildId сверены с manifest/config и создаваемым плейсом. Незамкнутые XML/asset-ссылки и отсутствующие SharedString проверены. Генерируемый бинарный файл имеет Roblox rbxl header; декодирование/повторная сериализация проверяют структуру, а не игровой запуск.
- Manifest SHA-256, размер и Adler32 проверяются для каждого файла. Загрузчик проверяет размер/Adler32 загружаемых файлов; это контроль целостности развёртывания, не криптографическая аутентификация сервера.
- Luau-компиляция server templates, client modules, loader и сгенерированного server code. Policy-тесты проверяют schema/NaN, cooldown, состояние, server hold timing, владение переносом/парой, пороги этапов и rate limit.
- Mock-тесты исполняют реальные networking/state factories: bootstrap buffering, отсечение старых событий, неверный build ID, encoded request mapping, порядок snapshot/state, удаление и новый персонаж. Отдельные mock-тесты исполняют реальный CombatServer: отмена dash, ragdoll network ownership, release cleanup и свежий clock sample у cached snapshot.
- Девять Python-тестов builder проверяют сохранение исходника, запрет чужого SHA и рекурсивного output, dangling/duplicate refs, детерминированность zip, восстановление BrickColor из неоднозначного XML и отклонение неверных бинарных типов. 13 существующих тестов импортера дополнительных костюмов сохранены.
- Независимая проверка кода закрыла найденные ошибки отмены dash, delayed pair effects, cached clock, teleport cleanup, costume timeout и рекурсивной сборки.

`Static_Checks.json`, `Build_Metadata.json` и `Release_Checks.json` содержат машинные результаты, build ID, checksum и проверенные ссылки. Итоговая сборка и повторная сборка должны давать одинаковые файлы; результат фиксируется в Release_Checks.

## Исправление сериализации 5 октября 2026

В первой выданной бинарной сборке Studio сообщил `Unexpected format 3 (expected 11)` у `SpawnLocation.TeamColor`. Прежняя проверка чтением тем же конвертером не выявляла этот дефект. XML обозначает BrickColor тегом int; при обратной записи без descriptor тип превратился в Int32. Builder теперь восстанавливает explicit BrickColor из типа PROP исходного бинарного файла. Создаваемый IntValue версии протокола также записывается как int64, соответствующий исходному бинарному типу. Значения цветов, карты и геометрия не изменены.

Новая проверка читает бинарные PROP напрямую и сравнивает типы всех сохранённых class/property с исходником. Она отклоняет оба прежних несоответствия до выдачи архивов. Serialization version 2 участвует в build ID. Пользователь впоследствии открыл пересборку и предоставил реальные Studio-логи её запуска; проверка автором в движке по-прежнему недоступна.

При проверке публикации выявлен отдельный дефект существующего GitHub workflow костюмов: refresh manifest удалял Adler32 из всех записей, и loader отклонял пакеты. Единый генератор реестра теперь сохраняет SHA-256, размер и Adler32 для builder и workflow. Регрессионная проверка реального batch import подтверждает сохранение checksum и остальных полей manifest; повторный refresh готового manifest должен оставлять его байты неизменными.

## Что изменено в логике исходника

### Исправление инициализации спавна 5 октября 2026

После открытия бинарной сборки пользователь сообщил о появлении в пустоте и смерти. В коде выявлены два небезопасных порядка: ожидание внешности до размещения на карте без фиксации тела и установка RequiresNeck/BreakJointsOnDeath после ApplyDescription. Кроме того, engine LoadCharacterAppearance выполнял свою загрузку параллельно серверной нормализации.

Исходный StarterCharacter теперь удерживается за HumanoidRootPart, имеет безопасные флаги Humanoid уже в шаблоне, а внешность применяет только сервер. CharacterAdded сначала размещает тело на существующем исходном спавне, обнуляет Velocity/RotVelocity, затем ждёт внешность и подключает игровые обработчики; после успешного подключения освобождает тело. Умерший, удалённый или заменённый персонаж не может завершить старую инициализацию. При отказе HTTP остаётся оригинальное R6-тело с конкретным предупреждением. Неактивные SpawnLocation не выбираются. Геометрия и координаты исходных карт/спавнов не меняются.

Новый run_spawn_tests.py исполняет настоящие World/CombatServer/Avatar с заменой только Roblox API: первый тест воспроизводил небезопасный порядок до исправления. Проверяются раннее размещение/фиксация перед yielding fetch, смена персонажа во время ожидания, смерть во время ожидания, отказ сервиса внешности и исключение disabled спавнов. Это проверки управления и жизненного цикла, а не симуляция физики. Повторный Roblox playtest исправления здесь не выполнен; устранение пользовательского симптома в движке ещё требует подтверждения.

### Исправление загрузки активной карты 5 октября 2026

Пользователь предоставил конкретный Studio stack: World.new:15, `The original active map is missing`; Main.new:15. Это подтвердило остановку всей серверной инициализации до подключения игровых обработчиков. Ранее конструктор искал только direct child с IsMap и требовал его немедленного наличия. Офлайн бинарный файл содержит Workspace.Crossroads, IsMap и оба ServerStorage-шаблона; причина отсутствия ожидаемого объекта именно в пользовательской сессии по одному stack не установлена.

Builder теперь извлекает точное имя исходной активной карты в WorldData.initialMap. World сначала использует соответствующую оригинальную модель с рабочими спавнами в Workspace; если её нет, клонирует одноимённую исходную модель из FunCombatData.Maps. Он ждёт появления зависимости не дольше 5 секунд, а при её отсутствии указывает имя и фактический состав Workspace/Maps. Голосование удаляет активную карту по ссылке и другие исходные карты по allowlist вместе с признаком IsMap/Spawns. Персонажи игроков, модели с прямым Humanoid и посторонние одноимённые модели сохраняются; поиск просматривает все совпадающие имена. Исходные модели/спавны и геометрия не заменены.

Добавлены семь проверок к пяти предыдущим: карта есть без IsMap, Workspace пуст с доступным оригинальным шаблоном, зависимость отсутствует с ограниченным ожиданием, а также четыре сценария совпадения имени карты с персонажем/посторонней моделью при запуске и голосовании. Старый код воспроизвёл предоставленный текст ошибки в сценарии без маркера; отдельный тест воспроизвёл удаление одноимённого персонажа до добавления защиты. Эти двенадцать сценариев проходят. Пользователь затем подтвердил в Studio восстановление Crossroads и server ready для build 8eb4ef3721b72ba2d005b9ff, но персонаж оставался закреплённым.

## Исправление раннего CharacterAdded и неподвижного персонажа

Пользователь предоставил реальный Client Output через 11 секунд после запуска: Players=1, Character=TodUntitled, HumanoidRootPart.Anchored=true, Health=100, WalkSpeed=16, JumpPower=50, PlatformStand=false. Это подтверждает физическую фиксацию тела; сообщение server ready само по себе не подтверждало завершение отдельной coroutine персонажа.

Обнаружена и воспроизведена конкретная ошибка обработчика: немедленный return при character.Parent=nil в начале CharacterAdded. Документированный порядок Roblox вызывает это событие до parenting модели в Workspace: https://create.roblox.com/docs/reference/engine/classes/Player#CharacterAdded. Поэтому нормальный новый персонаж ошибочно считался удалённым, а исходный anchored шаблон не освобождался; исключение или timeout даже не печатались. Тест с настоящими World/CombatServer/Avatar сначала воспроизвёл именно незавершённое подключение и Anchored=true.

Теперь отсутствие Parent до первого появления в Workspace означает ограниченное ожидание, а замена Player.Character/выход игрока по-прежнему отменяет обработку. После появления исходного R6-тела выполняются размещение, внешность, подключение механик и освобождение root. Успех печатает `FunCombat character ready: <username>; Anchored=false`; отсутствие модели/обязательных R6-частей более 10 секунд даёт конкретную ошибку. Добавлены три сценария: отложенное parenting, замена до parenting, отсутствие parenting до timeout. Все пятнадцать сценариев проходят. Это воспроизведение документированного порядка в mock, а не новый Roblox playtest; результат исправления в движке ещё не подтверждён пользователем.

Клиентские сообщения теперь передают намерения. Сервер сам выбирает подтверждённые цели/попадания, проверяет состояние, расстояние, задержки и hold. Этап пары нельзя задать произвольным числом: пороги 0.28/0.62/1 закреплены по исходным проверкам предыдущего значения. Dummy: 3 секунды cooldown, 4 на игрока, 20 на сервер. Перемещение/выход/respawn завершает общие взаимодействия без принудительного respawn оставшегося участника. Голосование использует реальные доступные спавны. Погода получает актуальную карту. Шкала/Completions, исходные Default/FD/Wall и костюмы включены.

Сетевой объект Microphone/TransmitBaseEvent в исходной карте не имел обработчика. Его копии удалены вместе с устаревшей сетью; новая механика микрофона не придумана. Исходные scripts и сторонние загрузчики сохранены для просмотра в source.

## Хват, задержки, походка, перенос, dynamic heads и female TorsoRig

Пользователь сообщил о неверном хвате, задержках, остановке ног и движения при переносе, отсутствующей dynamic face и female TorsoRig эффекте. Причины в коде: R6 grip attachment применялся без штатного поворота; первая загрузка presentation происходила на действии; Animator перезаписывал manual transforms, а любые боевые позы блокировали походку; welded carry assembly передавалась серверу и сохраняла второй активный Humanoid controller; нормализация обнуляла голову; морф требовал реплицированной ссылки партнёра и терял ранние bursts.

Исправлены соответствующие зависимости и lifecycle. Оригинальные Tool.Grip, 47 sequences и cooldown сохранены. Первые две атаки/equip/поза carrier не содержат исходных leg curves и сохраняют походку; третья атака/full-body/victim сохраняют исходные позы ног. PreSimulation после Animator используется при наличии API; старый Stepped fallback предупреждает об ограничении. Все ресурсы предварительно восстанавливаются до боевого ввода; mandatory model backend failure прекращает запуск. Hosted Failure/TimedOut именуют asset.

Dynamic head сохраняет реальные Head/Face/MoodAnimation и оригинальные MeshPart/FaceControls/Bones через head-only donor при необходимости, не меняя R6 тело. Neck, hair, prompts и внутренние references сохранены; retained Trail/Beam attachment references переподключаются. Родной mood не дублируется. Отказ/timeout и поздний ответ после respawn не закрепляют старое тело. User-ID dummy использует тот же адаптер. Реальная доступность головы/анимации и рендер лица в опубликованной игре не проверены.

Female TorsoRig восстанавливается в том же парном сценарии, что и исходник. Оригинальные ref/v/InteractionFX/Blood и ParticleEmitter, texture IDs, свойства и серверные counts сохранены. Серверные pairRole/pairId позволяют дождаться модели без ссылки партнёра; очередь bursts ограничена 128 событиями и двумя секундами, завершение очищает модели/очередь по ID. Это не добавляет постоянный idle-морф при выборе пола: такого поведения нет в доступном исходном обработчике.

Свежие офлайн-прогоны: 12 presentation, 8 avatar, 5 carry, 6 morph/effect и 16 spawn/map сценариев; Policy, client networking/state, server lifecycle; 9 builder и 13 outfit Python tests. Они исполняют реальные factories с заменой Roblox API, а не движок. Проверки воспроизводят задержанную репликацию, cleanup, отмену, deadlines, сохранение оригинальных ссылок и проверку дистанции. Binary roundtrip, compile, повторная сборка и проверка публикации фиксируются отдельно в Release_Checks.json. Геометрия не инспектировалась. Устранение симптомов в живом Roblox этой сборкой ещё не подтверждено.

## Не выполнено и ограничения

- **Roblox Studio и движок недоступны.** Не проведены импорт/публикация в Roblox, физический playtest, работа двух executor-клиентов, respawn/disconnect в живом сервере, фактическая загрузка анимаций/звуков/mesh и проверка rendered UI.
- **Executor model backend не тестирован в реальном executor.** Костюмы имеют настоящее скачивание `.rbxmx`, writefile, getcustomasset/getsynasset и GetObjects; после deserialization проверяются root count, membership и отсутствие Scripts/remotes. Поддержка локального `.rbxmx` зависит от executor. При невозможности загрузчик останавливается с ошибкой ресурса.
- **Hosted asset permissions не проверены.** Оригинальные mesh/texture/sound/AnimationId сохранены. Идентификатор не гарантирует доступность контента в конкретной опубликованной игре. Client PreloadAsync сообщает конкретные сбои, но здесь не запускался.
- JSON MeshPart fallback использует исходные MeshId/TextureID через SpecialMesh. Он не воспроизводит PBR SurfaceAppearance. Неподдерживаемые optional cosmetic классы/свойства перечисляются клиентом в предупреждениях.
- **Adonis и Kohl’s Admin не активированы.** Их требуемый hosted Roblox-код отсутствует внутри исходника; original models/settings/loaders сохранены в source/external. Собственная админ-панель игры и её исходный allowlist включены. Внешние админ-команды этих модулей остаются отдельной незавершённой интеграцией.
- Совместимость с конкретным старым Roblox-клиентом не подтверждена; версия/сессия не предоставлены. Сохранён исходный animation clock при номинальных 60 Hz; старые frame-rate-dependent особенности не сертифицированы.
- Dynamic heads/FaceControls и facial mood зависят от доступных engine API и разрешений настоящего avatar asset; legacy fallback не гарантирует dynamic face. Изолированная загрузка ограничена временем и сообщает отказ, сохраняя playable R6. In-flight ApplyDescription не допускается к gameplay до безопасного завершения.
- Builder предоставляет файлы. Публикация Roblox-плейса в аккаунт владельца не выполнена. GitHub обновляется отдельно и проверяется по реальным raw URL.

Это реконструкция с завершённой сборкой и офлайн-проверками; **полная рабочая копия игры в Roblox не подтверждена**.
