# Как добавить свои костюмы pp и boba

Это отдельное подключение **собственных обычных аксессуаров и одежды** к R6.
Оно не возвращает исходные NewMorphs, парную сцену или её анимации. Боевые
добивания остаются в существующем серверном боевом модуле. На сервер не нужно
добавлять костюмы: их увидят игроки с внешним клиентом из этого репозитория.

## 1. Подготовь свои модели

Сохрани каждый костюм из Studio отдельным XML-файлом модели: `pp.rbxmx` и
`boba.rbxmx`. Корневой объект должен быть Model или Accessory и иметь точное
имя `pp` либо `boba`. Скрипт не переименовывает объекты.

Model может содержать несколько Accessory и обычные Shirt, Pants, ShirtGraphic.
Каждому Accessory нужен Part/MeshPart с именем Handle. Остальные части этого
аксессуара должны быть соединены с Handle обычными Weld/WeldConstraint.
Не включай в костюм персонажа целиком, Humanoid, скрипты, Tools или анимации.

Крепление можно задать одним из двух способов:

- В Handle находится Attachment с тем же именем, что у нужного Attachment
  на теле R6. Клиент совмещает их, сохраняя заданные повороты и смещения.
- На Accessory установлен строковый атрибут `MountPart`: `Torso`, `Head`,
  `Left Arm`, `Right Arm`, `Left Leg` или `Right Leg`. В этом режиме свойство
  `Accessory.AttachmentPoint` задаёт CFrame смещения относительно этой части.
  Этот вариант подходит и при отсутствии стандартных Attachment у старого R6.

Необязательный булевый атрибут `MatchBodyColor=true` на конкретной детали
костюма окрашивает её в цвет Torso. Остальные цвета остаются как в твоём файле.
Тело персонажа не скрывается. Новые Shirt/Pants временно заменяют старую одежду
только в локальном отображении; после снятия костюма она восстанавливается.

Для старого клиента надёжнее обычные Part + SpecialMesh. MeshPart использует
имеющийся в проекте запасной загрузчик; UnionOperation здесь не поддерживается.
Ссылки на mesh/texture должны быть доступны именно твоему целевому клиенту.

## 2. Загрузи модели прямо на GitHub

1. Открой [imports/outfits](https://github.com/a65407112-boop/FunCombatAssets/tree/main/imports/outfits).
2. Нажми **Add file → Upload files**, добавь `pp.rbxmx` и/или `boba.rbxmx`.
   Бинарные `pp.rbxm` и `boba.rbxm` тоже поддерживаются. Для одного имени
   загружай только один формат: наличие обоих вызывает понятную ошибку.
3. Нажми **Commit changes** в ветку `main`.
4. Открой **Actions → Import own costumes** и дождись зелёной отметки.
5. Повторно запусти существующий `loader.lua` в игре.

Весь импорт выполняет GitHub Actions. На твоём компьютере Python устанавливать
не нужно. В игре нет кнопки импорта, редактора моделей или приёма файлов от
игроков. Серверный place не получает эти модели; внешний клиент загружает только
готовые JSON-пакеты для отображения.

GitHub проверит имена, Handle, классы и внутренние ссылки, сохранит исходные
файлы в `imports/outfits`, создаст `assets/outfits/*.json` и копии `.rbxmx`, затем
обновит `config/outfits.json` и `manifest.json` одним коммитом. Если один файл
неправильный, подготовленные ранее модели не заменяются. Можно начать с одного
костюма. До первого импорта в слотах нет готовых моделей и подставных замен.

Если запуск красный, открой его шаг **Prepare uploaded costumes**: там будет
конкретная ошибка. Исправь файл и загрузи снова. Если GitHub запрещает запись
коммита, проверь **Settings → Actions → General → Workflow permissions**:
workflow нужны права записи содержимого репозитория. Повторный запуск доступен
через **Actions → Import own costumes → Run workflow** на ветке `main`.

## 3. Gender продолжает выбирать модель

| Выбор Gender | Костюм |
| --- | --- |
| Male | pp |
| Female | boba |
| Fembxy | boba |

Это соответствие находится в `byGender` файла `config/outfits.json` на GitHub.
Можно изменить его или поставить пустую строку для отключения костюма у одного
выбора. После Commit changes тот же workflow обновит manifest автоматически.
Смена Gender подтверждается сервером; клиенты с загрузчиком отображают нужный
костюм у каждого игрока. Выбор сохраняется при возрождении в текущей сессии.

Смена выбора, возрождение и повторный запуск loader очищают старые крепления.
Запоздалый ответ загрузки не заменяет более новый выбор. При отсутствии нужного
крепления клиент сообщает имя аксессуара и оставляет обычного персонажа.
Костюм не отправляет запросы урона и не меняет состояние боевого сервера.

Проверены экспорт и логика с заменами сервисов движка. Внешний вид твоих
будущих моделей и работа в Roblox/2021 ещё требуют проверки в игре.
