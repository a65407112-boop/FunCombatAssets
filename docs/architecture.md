# Устройство проекта

Builder читает исходный Roblox DOM, сохраняет окружение, физику, обе карты и серверные зависимости. Перед удалением клиентских контейнеров он экспортирует исходные ресурсы. R6-имена Torso/HumanoidRootPart/Humanoid и имена окружения сохранены. Имена сетевых объектов, действий, событий и подписи промптов кодируются; соответствия находятся в config за пределами плейса. Это кодирование не заменяет авторизацию.

В ServerScriptService находится FunCombatServer: Policy проверяет намерения и владение; CombatServer ведёт состояния, hit windows, урон, cooldown и персонажей; PairSystem ведёт оригинальные варианты Default/FD/Wall и шкалу; Ragdoll управляет физическими связями; World управляет общими объектами карты; Voting выбирает исходные карты. Промпты используют исходные клавиши, расстояния, UI offset и удержание, а сервер повторно проверяет эти условия.

В ReplicatedStorage три сетевых объекта: запрос намерений RemoteEvent, подтверждённые presentation-события RemoteEvent, snapshot RemoteFunction. Version и BuildId сверяются до запуска. Состояния и анимации имеют revisions; при bootstrap события буферизуются до применения snapshot. Периодический snapshot восстанавливает пропущенное состояние. Выход и смена персонажа освобождают взаимодействия, anchors, welds и эффекты.

Внешний клиент восстанавливает GUI, оружие и эффекты из типизированного JSON: создание, свойства, родители, ссылки. AnimationPlayer применяет экспортированные исходные Pose.CFrame по серверному времени. NewMorphs восстанавливаются из оригинального sanitized XML через локальный model backend executor, включая три embedded UnionOperation. Их физическое влияние локально отключено. Серверу достаточно стандартных авторитетных R6 тел.

Оригинальные Lua scripts сохранены в source/scripts с картой путей source/scripts.json. Они служат исходными данными и не исполняются внешним загрузчиком. Рабочие адаптации лежат в Builder/templates/server и client. Исходные внешние админ-модели сохранены отдельно: их hosted require-код отсутствует в приложенном плейсе.

Отчёт отделяет структурную проверку, компиляцию и mock-тесты от запуска движка. Совместимость конкретного старого Roblox-клиента, hosted asset permissions, GetObjects executor и визуальный результат остаются непроверенными.
