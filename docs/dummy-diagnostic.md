# Проверка dummy без консоли

`spawn`, `:dummy` и `:spawndummy` не дали результата в опубликованной игре пользователя. Причина live отказа пока не подтверждена. Проверки ниже не заменяют запуск в Roblox.

`diagnose_dummy.lua` — самостоятельный скрипт, который основной loader не запускает. Открытие окна читает локальные данные и не посылает команд. Нажмите **Test dummy** один раз, дождитесь **Test finished** (8 секунд), затем **Copy report** и отправьте отчёт. Если executor не разрешает clipboard, кнопка выделяет текст для ручного копирования. При отсутствующем/несовместимом runtime окно всё равно выводит отчёт, но запрос создания не отправляет.

Кнопка читает настоящий реестр команд исходного Kohl’s Admin Infinite через его штатный начальный запрос `KuID`. Так можно отличить отсутствующие `dummy`/`spawndummy` от отсутствия ответа. Затем она вызывает только `ctx.combat:request("SpawnDummy")`: сохраняются проверки клиента, серверная авторитетность, флаг `AllowDummys`, cooldown и лимиты. Прямой обход серверного протокола не добавлен. Весь код совместимого серверного build `6a27795e99d5b46ef4847aec` и основной клиент оставлены прежними.

Скрипт читает фактический реплицированный `AllowDummys`, состояние персонажа и live build/version; перехватывает доступные raw Error и новые NPC State сообщения в течение ограниченного окна. Не меняет конфигурацию, аватар, геометрию, права или боевое состояние. Повторное нажатие не создаёт повторный запрос. Закрытие, повторный запуск и истечение 8 секунд снимают его наблюдателей.

| Поле/статус | Что подтверждает |
|---|---|
| `kohlRegistry.received=true`, `dummy=false` | Сервер ответил настоящим списком, команда в нём не найдена. |
| `kohlRegistry.status=no_reply` | Ответ на запрос списка не наблюдался; отсутствие команды этим не доказано. |
| `client_unavailable` | Живой внешний combat runtime отсутствует, остановлен или не инициализирован. |
| `protocol_mismatch` | Фактический сервер не совпадает с runtime; запрос создания не отправлен. |
| `client_rejected` | Обычный input owner вернул false; рядом сохранено состояние персонажа. |
| `clientRequestAccepted=true` | Обычный клиентский input owner принял запрос; не доказывает приём/выполнение сервером. |
| `server_errors_observed` / `serverErrors` | Получены точные raw ошибки сервера в этом окне; они могут относиться к другим действиям. |
| `server_npc_observed` / `newServerNPCs` | Наблюдалась новая регистрация NPC в авторитетном состоянии; протокол не доказывает владельца этого запроса. |
| `no_server_result_observed` | В окне не наблюдались новый NPC или ошибка; это не подтверждённый отказ. |
| `context_changed` | Во время принятого запроса сменился персонаж или runtime; наблюдение нельзя считать проверкой прежнего контекста. |

В протоколе 4 нет request ID или адресного подтверждения успешного создания dummy. Поэтому диагностический скрипт явно хранит `ownershipConfirmed=false`: чужой новый NPC не выдаётся за доказательство выполнения собственного запроса. Он не вызывает серверный Snapshot и не имеет бесконечных повторов/ожиданий. В live коде обычный серверный путь `SpawnDummy` игнорирует возвращаемые `World:dummy` причины части отказов; исправление этого потребует согласованного нового серверного файла, если диагностика подтвердит необходимость.

Офлайн: `run_dummy_probe_tests.py` исполняет настоящий диагностический chunk с engine doubles, включая состояния отсутствующей команды/ответа, реальный mismatch, false request, raw ошибки, корреляционные ограничения, cleanup и Copy. `run_combat_input_tests.py` исполняет настоящие `client/combat.lua` и `client/networking.lua` с заменой недоступных Roblox services/signals: обычный/современный чат, ID, debounce, блокирующие состояния, разделение native команд и teardown. Это не запуск Roblox и не свидетельство исправления пользовательского live отказа.
