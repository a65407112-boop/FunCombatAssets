# FunCombat — сервер и внешний клиент

Обновление уведомлений 8 октября: клиент больше не включает исходный непрозрачный loading screen `yeah` при Notice. Успешный `spawn` / `:dummy` / `:spawndummy` проходит без popup; ошибки и сообщения карты/погоды остаются короткими уведомлениями. Это client hotfix для текущего server build **5ff8518b983483f077022b2a**, protocol **4**: достаточно повторно запустить свежий loader, сервер перепубликовывать не нужно. Старые инструкции новой серверной публикации ниже относятся к предыдущим парным поставкам.

По новому live сообщению владельца лицо теперь отображается правильно, но другие части тела чёрные. Причина этого второго дефекта пока не установлена. Отдельный ручной `diagnose.lua` с кнопкой Copy теперь сохраняет реальные цвета всех R6 частей, BodyColors, applied description/BodyPartDescription и текущее освещение. Он не перекрашивает персонажа и не исследует геометрию. Roblox engine здесь недоступен.

Проект собран из `FunCombat_Renamed2.rbxl` с SHA-256 `a14ab714b5b3233a8e05fc5567ce1b9a7dc700ced2ccb2e13771c025f64142b0`. Исходный файл builder не изменяет. Геометрия и визуальное сходство не проверяются по просьбе владельца.

Серверный файл: **funcombat_server.rbxl**, также доступен **Game_Server.rbxlx**. Сервер определяет попадания, урон, cooldown, падение, восстановление, перенос, исполнения, парные взаимодействия, шкалу, Completions, голосование, погоду и общие результаты действий.

Внешний пакет содержит шесть исходных оружий, 47 исходных KeyframeSequence, оригинальные LowerRig/TorsoRig, интерфейсы, звуки, эффекты и ссылки на Roblox-контент. JSON восстанавливает Instances, свойства и внутренние ссылки. Три оригинальных UnionOperation, 11 MeshPart и один SurfaceAppearance сохранены как минимальные native-зависимости в ReplicatedStorage под закодированными именами. Клиент клонирует их исходные данные загрузки, а полные модели и связи восстанавливает извне. SurfaceAppearance остаётся на настоящем MeshPart; защищённые mesh/PBR свойства не перезаписываются. Локальный GetObjects для исходных ресурсов не требуется; исходные `.rbxmx` также экспортированы.

Обновление 8 октября: новая серверная сборка устраняет воспроизведённый путь отказа при потерянной `Configuration/AllowDummys`. Builder сохраняет точную исходную конфигурацию в `ServerStorage.FunCombatData.WorldSettings`; сервер восстанавливает отсутствующий контейнер/флаг при старте, сохраняя явно выставленное `false`. Отказы dummy теперь приходят игроку через исходные Notice/Error; успех сообщается после настоящего combat bind. Cooldown 3 секунды, лимиты 4/20, серверные проверки и исходный DummyRig сохранены. Нужно опубликовать новый `funcombat_server.rbxl`, перейти в новый сервер и запустить loader. Это новая парная сборка; старый сервер с build `6a27795e99d5b46ef4847aec` не подходит к обновлённому manifest. Live причина исчезновения флага и результат исправления ещё требуют Roblox.

`loader.lua` получает manifest/config/modules по raw GitHub URL, проверяет protocol **4** и точный build ID, соблюдает зависимости, восстанавливает состояние и обрабатывает повторный запуск. Настройки владельца, репозитория и ветки находятся только в начале loader.

Текущая парная сборка native R6 head: **5ff8518b983483f077022b2a**. Требуется опубликовать новый серверный файл и войти в новый сервер перед запуском обновлённого loader.

Обновление головы 8 октября: Avatar больше не считает присутствие FaceControls доказательством правильной головы. Из исходного HumanoidDescription создаётся отдельный native R6 avatar; его настоящая голова с FaceControls, bones, texture/PBR и head metadata подключается к сохранённому R6-телу игры. Исходные Neck, hair welds, attachments и игровые промпты переподключаются, старые classic mesh/decal не перекрывают dynamic head. Для classic face сохраняется настоящая native decal. Геометрия не исследуется.

Исправлена подтверждённая ошибка facial mood: MoodAnimation содержит ID пакета, а не самого AnimationClip. Сервер берёт настоящий Animation child из engine Animate.mood или исходного hosted пакета и сохраняет отдельный FunCombatMoodClipId. В StarterCharacter и DummyRig остаётся только пустой LocalScript Animate как native facial hook; походка и боевые позы по-прежнему во внешнем клиенте. Поздний native track заменяет только локальный fallback; чужой/native track не останавливается. Диагностика остаётся ручной и отдельной. Live рендер чёрной головы ещё не проверен: это новая стратегия загрузки, а не доказанная причина старого дефекта.

История совместимого исправления голосования 7 октября: GUI теперь читает серверные записи `{name=...}`, показывает исходные карточки карт и обновляет счёт голосов. Это совместимое обновление клиента для существующего server build `6a27795e99d5b46ef4847aec`; достаточно повторно запустить loader, `.rbxl` заменять не требуется. В выданном серверном файле `Workspace.Configuration.AllowDummys` равен `true`. Отдельный `diagnose.lua` показывает фактический реплицированный флаг в запущенной игре, состояние персонажа и доступные ошибки Kohl; он не отправляет команды. Причина live отказа `spawn`, `:dummy` и `:spawndummy` пока не подтверждена. Дополнительный самостоятельный `diagnose_dummy.lua` открывает окно без сетевых действий; только кнопка **Test dummy** читает реестр настоящих команд Kohl и делает один обычный запрос dummy, наблюдая до 8 секунд. Затем **Copy report**. [Точные ограничения и поля отчёта](docs/dummy-diagnostic.md). Основной loader диагностику не запускает, серверный файл для неё менять не нужно.

Походка других игроков: наблюдатель сохраняет уже реплицированный оригинальный locomotion track, не запускает поверх него второй и не меняет чужие speed/TimePosition. При позднем появлении трека убирает только собственный fallback. Наклон чужого персонажа рассчитывается из наблюдаемого горизонтального движения, поскольку Humanoid.MoveDirection не реплицируется; локальные управление и исходные коэффициенты сохранены. Обоим игрокам следует повторно запустить loader. Пять новых сценариев проверены офлайн; вид походки на двух настоящих клиентах после этого обновления ещё не подтверждён.

Обновление 5 октября: восстановлен исходный R6 хват оружия, походка во время анимаций без поз ног и управление при переносе. Оригинальные ресурсы предварительно загружаются до подключения боевого ввода. Сервер сохраняет настоящие head/face/mood аватара; для dynamic head на R6 при необходимости переносит только оригинальную голову из временного Roblox R15-моделя. Female TorsoRig и его исходный InteractionFX ожидают репликацию персонажа и очищаются по идентификатору взаимодействия. Геометрия не проверялась; результат в движке ещё требует теста.

Обновление 6 октября: исправлен подтверждённый путь отказа при загрузке встроенных unions без local GetObjects. Полная ошибка loader доступна в отдельном окне с копированием. Настоящие head/accessory/mood ресурсы предварительно загружаются по мере репликации; ранние ошибки сервера сохраняются для позднего клиента. Причина чёрного рендера головы в пользовательской игре не подтверждена: обработка загрузки и диагностики проверена офлайн, визуальный результат требует Roblox.

Обновление 7 октября: воспроизведён PC fatal Maxwell `SurfaceAppearance can only be parented to MeshParts`. Оригинальные MeshPart теперь клонируются с сохранением native load state на ПК и телефоне; небезопасные запись MeshId и конвертация в Part/SpecialMesh убраны. Исходные Size, CFrame, TextureID и соединения сохраняются без произвольного уменьшения. Костюм входит в персонажа с авторскими смещениями до создания torso-to-ref weld, как в NewChanger. Новый серверный файл нужно опубликовать целиком. Размеры оружия, видимость female torso и male torso в настоящем клиенте после этого исправления ещё не подтверждены.

Оригинальный Kohl’s Admin Infinite подключён через его реальный module ID **1868400649** и сохранённые native Settings/Custom Commands. Creator получает исходные полномочия Kohl автоматически. Админ-панель игры и команда `:dummy [userId]` проверяют на сервере фактического владельца и явно настроенный numeric UserId **11556197791**. Единственный исходный параметр — `config/admin.json`; builder включает его также в оригинальный список Kohl Owners (power 5). Смена аватара и username не меняет grant. Старый username allowlist удалён. `:dummy` создаёт исходный combat dummy; `:dummy 261` использует внешность указанного Roblox UserId. Действуют исходные ограничения: 3 секунды, 4 dummy на игрока, 20 на сервер.

Новый отказ `WeldConstraint.Part0Internal` воспроизведён: runtime JSON и assets factory используют доступные `Part0`/`Part1` с исходными целями. Оба полных оригинальных costume-пакета проверены на восстановление Instances и соединений без инспекции геометрии. Отдельный **`diagnose.lua`** запускается вручную даже после failed loader; основной loader его не вызывает. Он показывает отчёт прямо в игре с кнопкой Copy report; консоль не нужна. При недоступном clipboard можно выделить весь текст и скопировать вручную. Повторный запуск заменяет окно, Close закрывает его. Причина чёрного head rendering остаётся непроверенной в движке.

Отдельный [head_test.lua](head_test.lua) проверяет чёрный фон конкретной динамической головы из живого отчёта 7 октября. Он показывает Test texture / Restore / Copy report, накладывает точные исходные RGBA-пиксели поверх прежнего Head.Color через native SurfaceAppearance Overlay и не меняет обычный loader или сервер. Это обратимое сравнение, не подтверждённое исправление рендера. Нужны современные EditableImage/SurfaceAppearance API; отказ виден в окне. [Инструкция и ограничения](docs/head-test.md).

Roblox Studio, движок, executor и старый клиент в среде сборки отсутствуют. Офлайн-проверки не подтверждают игровой запуск, сетевую физику, рендер головы или разрешения на hosted assets. Kohl остаётся hosted Roblox-зависимостью и создаёт свои native UI/scripts/remotes во время запуска; отказ/timeout сообщает точную причину и не блокирует combat. Adonis не активирован; его исходные настройки сохранены в `source/external`. Эта сборка не сертифицирована как полная рабочая копия в движке.
