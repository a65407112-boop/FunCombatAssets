# Portable Fun Combat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish an independent client-only combat adapter using the existing FunCombat assets.

**Architecture:** A virtual combat core drives local R6 avatars and an in-process presentation bus. Existing asset/animation/weapon/audio modules consume the bus and proxy models. A standalone loader verifies pinned shared resources and owns all cleanup.

**Tech Stack:** Roblox Luau (Lua 5.1-compatible syntax), original JSON/RBXMX resources, Python/liblua5.4 offline checks, GitHub Git-data publication.

**Spec:** docs/superpowers/specs/2026-10-12-portable-design.md

## Global Constraints

- No server protocol or remote transport; only virtual health and local proxy physics.
- Preserve original resource references/grips; no replacement weapon geometry.
- Preserve real avatar health/root/joints, restore local visibility on cleanup.
- Two local prompts: Glory and Carry; no separate Execute GUI button or paired morphs/animations/audio.
- Default Bat; all six weapon choices with explicit native-import errors.
- HoldDuration 0.3 and interaction distance 6 for local prompts.
- No Roblox, physics, rendering or executor success claims without engine evidence.

## Review Focus

- CharacterAdded before Workspace parenting: await mounting; reject old generations.
- Removal during carry: release both records, restore gait and remove stale prompts.
- Unsupported native model import: keep Bat usable, identify the failing weapon.
- Source colors and visibility changed by the game/camera: mirror source appearance and restore local presentation safely.
- Repeated execution while HTTP is pending: cancel old ownership before hiding new source characters.
