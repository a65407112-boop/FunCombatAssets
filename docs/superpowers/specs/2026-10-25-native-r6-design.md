# Native R6 and readable runtime names

The user requested a new server place and matching GitHub update, then clarified
that the saved custom StarterCharacter must be removed, standard R6 avatars
must retain morphs and dynamic heads, and the external loader must restore
normal names only when it runs. They explicitly asked to proceed. The attached
FunCombat_Renamed.rbxl could not be accessed, so this change uses the existing
server/funcombat_server.rbxl at c10245231cc4decc05cc3b8f7cfa7ec7a9a92986.

Keep all saved map/environment models and server-authoritative gameplay. Retain
the two distinct NPC rigs as saved server templates rather than enforcing a
single saved character. Remove the player StarterCharacter and enable native
appearance and dynamic-head loading. Do not fetch and reapply a player's user
avatar or replace their head during combat initialization: preserve the body,
head, facial animation data and morphs Roblox or another morph system supplies.
Support compatible R6 morphs and replacement R6 Player.Character models; R15
animation retargeting is outside this change.
The user subsequently clarified that players must have blocky bodies: strip
non-head R6 CharacterMesh packages, including those arriving after spawn, while
preserving head packages, dynamic heads, body colors and accessory/morph content.

Saved renamable instances, including rig parts and attachments, use opaque
names. Server-only NPC templates restore engine names on their clones before
binding. Runtime player bodies are generated by Roblox. The external loader
restores client-visible map/object/stat names locally from explicit bindings;
server names stay consistent and authoritative across clients. Built-in service
and engine container names remain compatible. Local renaming must be reversible
on unload and safe for late replication and repeated loader runs.

The existing place can be upgraded without the unavailable reference by reading
its packed server modules and typed RigData. This preserves opaque map/native
payloads and avoids replacing the map. An upgrade tool must reject mismatched
input instead of silently producing mixed protocol/build identities. Future
source builds must apply the same upgrade.

Verification covers standard-avatar preservation, morph replacement, failed or
late appearance work, local-name restoration and cleanup, saved names, NPC
template references, binary roundtrip, client/server syntax and repository
integrity. Roblox Studio rendering and real multiplayer playtests are unavailable
and must be reported separately from offline verification.
