# Исправление формата BodyTypeScale

Версия файла, опубликованная как Roblox version 14, содержала шесть
`HumanoidDescription`-свойств с бинарным типом Float64 (5). Studio ожидает
Float32 (4) и останавливает открытие с сообщением `Unexpected format 5
(expected 4)` на `BodyTypeScale`.

Причина в сборщике: при восстановлении сохранённых NPC исходная таблица
типов не содержала класса `HumanoidDescription`, а общий экспорт чисел
подставлял `double`. Публикация через Open Cloud вернула номер версии,
хотя этот файл не открывался в Studio. Зелёный результат подтверждал
загрузку байтов, а проверки Studio в этом процессе не было.

В `server/funcombat_server.rbxl` исправлены ровно шесть PROP-блоков:
`BodyTypeScale`, `DepthScale`, `HeadScale`, `HeightScale`,
`ProportionScale`, `WidthScale`. Остальные блоки бинарника сохранены
побайтно, включая карту, скрипты, имена и связи. Build ID остался
`f482ff99012fc0fc13c56d7a`. Числа приведены к точности Float32.

Сборщик теперь задаёт этим полям правильный тип и останавливается, если
для нового числового поля не найден известный тип хранения. Проверка
бинарника запускается после сборки и перед публикацией через GitHub.

Проверки: 6 новых регрессионных тестов, 41 тест Builder, 7 тестов команды
публикации; сверены 250 Float32/Float64-свойств с API dump Roblox Studio
`version-7aaa6838d36c4448`, несоответствий не осталось. Исправленный файл
повторно прочитан rbxmk. Подробности и SHA256: `RBXL_Format_Checks.json`.

Открытие в настоящем Roblox Studio и запуск игры здесь не проверялись.
Проверка схемы и сторонний декодер не заменяют открытие файла в Studio. Откройте заново
скачанный файл; ранее скачанная копия сама не обновляется.

Исправление формата не меняет статус модерации игры и не было автоматически
опубликовано в Roblox.
