# Source-specific architecture

The server modules are supplied in the full project's `Builder/templates/server/`. Main initializes the source map, prompt templates and a versioned protocol. CombatServer owns action allowlists, original damage/timings, oriented-box target tests, downing, stun, knockback, R6 ragdoll, recovery, carrying, executions, killstreak and awakening. Rules and MoveData contain source constants. Voting owns the two original maps; World owns wall-contact detection, environmental music, TV controls, teleport pads, killboxes, Cirno rotation and weather.

Clients send only Equip/Swing/Dash/GetUp/Emote/Vote/Drop intent through Action. Carry and execution use server ProximityPrompt events with state, distance and hold checks. Attack victims and amounts are computed on the server. The original wall-bounce client CFrame request is replaced with server contact/geometry checks. State and animation revisions protect against late snapshot rollback. Voting and weather have separate revisions.

The client consists of factories initialized in `manifest.json` order. cleanup owns all generated instances and connections. assets reconstructs original typed data. networking checks the protocol and obtains snapshots. state handles monotonic updates; animations applies original pose CFrames to the existing R6 rig. characters handles original movement IDs and leaning. weapons installs the original visual handles via the source grip. gui/effects/audio/interactions/combat present the state and collect input. The original buildthomas Rain module is wrapped with resource cleanup, and weather uses source lighting templates. main requests initial state only after subscribers are ready.

No duplicate character rig is created. There is no separate safe cosmetic morph collection in this source: NewMorphs belongs to the excluded explicit interaction branch. The standard original R6 proxy remains the character body. All six weapon presentations share the original combat rules.

Asset JSON preserves instance classes, names, writable properties, internal references and source IDs. Companion model XML retains extra original properties. New MeshParts cannot always receive MeshId at runtime, so the supported fallback is the same original mesh through SpecialMesh and original mesh bounds. That fallback does not reproduce PBR SurfaceAppearance. Legacy unsupported cosmetic classes/properties produce warnings. Embedded map CSG remains in the server DOM and is not rebuilt as substitute geometry.

The old custom animator interprets each absolute Keyframe.Time as a segment duration and advances one keyframe per frame, using Speed 50/250. `AnimationClock="source"` models those nominal 60 Hz durations; it does not multiply a normal animation track by 50. `keyframes` is an optional authored-time interpretation. Source poses and animation data are retained in both cases. Original animation connection leaks and failed joint resets are corrected.

Intentional corrections include trusted damage/target removal, cooldown enforcement, completed-hold ordering tolerance, cleanup on removal, single dummy instead of a duplicate, spawn modulo for more players than spawn slots, per-character teleport debounce, active-map weather selection and the originally inert Workspace KillPart handler. These are adaptations, not claims that every source bug or pixel is reproduced.

No repository upload, hosted-asset access test, Roblox import, physics simulation, multiplayer playtest or 2021 compatibility certification has been performed. The source's explicit interaction branch and built-in chat /e controller are outside this implemented scope. See the full package Validation_Report.md for evidence.

Protocol version 2 includes deterministic prompt identifiers generated from the source checksum and separate name/text namespaces. The readable mapping is stored only in `config/identifiers.json`, outside the place. The server stores Custom-style prompts with encoded text; interactions.lua sets original labels and Default style locally, restoring encoded values during cleanup. Gameplay is executed by the server-owned prompt handlers. Exact generated server sources are also included in `Builder/generated/server/` in the complete archive.
